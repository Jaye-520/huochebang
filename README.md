# X001 货车帮司机货源采集

## Windows 一键启动

从 Git 克隆后如果要自行打包，请先在 PowerShell 中运行
`winget install --id astral-sh.uv -e` 安装 uv。安装后重新打开终端，运行
`uv --version` 确认可用。也可以参考 [uv 官方安装文档](https://docs.astral.sh/uv/getting-started/installation/)。
在项目根目录运行 `.\scripts\build_launcher.ps1`，生成 `dist\X001.exe`。
已有打包好的 `X001.exe` 时，可以直接使用随附的 uv，无需运行打包脚本。
将 exe 放在项目根目录，或保留在根目录下的 `dist` 文件夹中，然后双击启动。
启动器会作为「X001 智能控制中心」自动准备 Python 3.14、安装依赖、初始化本地数据、
启动网页服务并检查手机；就绪后直接打开网页操作台，无需手工先启动网页。
网页服务固定使用 `http://127.0.0.1:8765`，避免运行中更换端口导致操作台地址不一致。
首次启动需要联网下载运行环境和依赖，界面会显示当前准备阶段，诊断日志默认收起。
之后启动会复用已安装环境。

手机连接、USB 调试授权、锁屏和货车帮司机状态会分项显示。
程序会尝试唤醒手机并在安全条件下启动货车帮司机；
USB 授权、锁屏密码以及采集线路仍需在手机上确认，避免绕过安全校验或误采错误线路。
失败时界面会指出具体原因，并提供「重试启动」「重新检测手机」和「查看原因」入口。
关闭启动器会停止网页服务，并等待正在运行的采集任务安全退出后再结束进程。

如果 Windows 阻止运行，请确认 exe 来自可信的项目目录后选择“仍要运行”。
项目数据保存在 `data\` 文件夹。启动器不会打包或上传本地采集数据。

## 网页操作台

运行 `uv run x001-web`，然后在浏览器打开 <http://127.0.0.1:8765>。
网页直接读取 `data/x001.sqlite3`；明细与采集操作台按固定间隔刷新，线路规划首页通过「刷新数据」按需更新。
网页分为「线路规划」「货源明细」「采集操作台」三个页面。
线路规划首页以起终点为主入口：输入或在地图上依次选择两个城市后，左侧按货源量、数字运价覆盖、里程范围和最近采集时间比较候选线路；选中线路后，地图、沿途节点和右侧货源清单进入同一线路上下文。参考走廊可叠加对照，点击节点可临时查看该节点货源而不清除当前线路。点击货源会打开独立详情弹层，核对原始地点、字段和截图，不会压缩货源列表。首页同时提供区县定位、区县端点选择和全部重置；数字运价覆盖只统计带数值的运价，协商价不计入。地图仅展示城市或区县近似位置及示意连线，不计算实际道路、距离或货车可通行路线。
在手机上打开目标线路并设置筛选条件后，可以在网页的「采集操作台」启动采集；
网页启动采集前需要选择当前线路。若手机顶部识别出的线路与所选线路不一致，
采集器会停止，不会把新货源写到错误线路。
也可以只处理已有截图或重新识别全部截图。采集期间请保持手机解锁，并让程序独占手机操作。
在「货源明细」可按线路、车型、车长、需要车数、运价状态和关键词组合筛选，并导出当前筛选结果的 Excel 表格；待核对记录会在序号格附批注。
点击货源可查看完整字段和原始详情截图。

操作台的「清除全部采集截图」会删除 `data/captures/` 中的采集图片，并清空数据库中的截图关联；
已识别的货源数据和货源编号保留。清理后旧截图无法重新识别，
新截图文件夹从 `1` 重新编号。运行中或有待处理截图时不允许清理。

网页默认只允许本机访问。需要在同一局域网的手机浏览器查看时，
可运行 `uv run x001-web --host 0.0.0.0`，再用电脑的局域网 IP 和端口 8765 访问。
此模式启动时会在终端显示访问密码，浏览器会弹出登录框，用户名为 `x001`。
这是未加密的 HTTP Basic 登录，只适用于可信任的局域网；请勿在不可信网络使用，
也不要将此服务暴露到公网。

X001 从货车帮司机的线路列表读取货源。程序通过 ADB 和 UiAutomator 操作手机界面，保存详情截图，识别货源字段并写入 SQLite。你在手机上选择线路和筛选条件，程序从当前列表开始采集；到达「推荐货源」分区后回顶刷新并继续，直到到达列表末尾或被限量、中断。

## 环境准备

- Python 3.14 或更高版本，使用 uv 安装依赖。
- 默认连接小米 MIX 3，ADB 序列号为 `7450df55`，竖屏分辨率为 `1080 × 2340`。采集器的页面布局和手势以这台设备上的货车帮司机为验证基准。
- 手机开启 USB 调试、保持解锁，并授权电脑连接。项目自带 Windows 版 ADB。其他平台需在 `PATH` 中提供 ADB。
- Windows 默认使用系统简体中文 OCR 做快速初识别。字段需要复核时，会对重量、运价、装卸地、货物、车型、货主、里程和备注运行 PP-OCRv5 mobile/OpenVINO 第二意见。只有重量范围的分隔符错误、或运价单位同时得到列表和详情一致佐证时，才自动修正并清除对应复核标记；其他二次意见保留给人工判断。首次二次识别会从模型仓库下载约 20 MB 权重。显式使用旧 PP-OCRv6 Medium 后端时，Windows 上的 PyTorch 需要 Microsoft Visual C++ 2015–2022 x64 运行库。

在项目根目录安装依赖，确认手机在设备列表中显示为 `device`。

```powershell
uv sync
uv run x001-init
.\src\x001\platform-tools\adb.exe devices -l
```

`x001-init` 会创建本地的 `data/ocr_images/`、`data/ocr_results/`、
`data/captures/` 和 `data/x001.sqlite3`。这些数据路径已加入 Git 忽略规则。
初始化可重复运行，已有图片和货源记录会保留。单图 OCR 命令可直接读取指定路径，
采集命令也会在运行时初始化所需的数据库。
日常采集与导出统一使用 `data/x001.sqlite3`；无需为每轮采集新建数据库。

## 运行采集

在手机上打开目标线路并设置筛选条件。运行期间让程序独占手机操作。

```powershell
uv run x001-collect
```

首次使用可限制采集量。保存好的截图可在稍后继续识别。

```powershell
uv run x001-collect --max-orders 5
uv run x001-collect --process-only
```

| 参数 | 用途 |
| --- | --- |
| `--database 路径` | 高级选项：指定 SQLite 文件。日常使用省略此参数，统一追加到 `data/x001.sqlite3`。 |
| `--max-orders 数量` | 达到指定采集量后结束本轮，适合真机试跑。 |
| `--capacity 数量` | 限制采集中、排队及识别中的截图组总数，默认 3。达到上限后，手机停在线路列表等待。 |
| `--ocr auto\|windows\|hybrid\|rapid\|paddle` | 默认 `auto` 在 Windows 上使用 Windows 初识别，并按需运行 PP-OCRv5 二次识别；`windows` 只运行 Windows OCR，`hybrid` 强制启用双引擎，`rapid` 单独使用 PP-OCRv5 mobile，`paddle` 保留旧 PP-OCRv6 Medium。 |
| `--process-only` | 只处理当前数据库中待识别、处理失败或上次中断的截图组。 |
| `--reprocess-all` | 用已有截图重新识别和清洗已采集记录，无需连接手机。 |

采集日志会显示线路识别文字。识别完成后，可按该文字导出单线路货源表：

```powershell
uv run x001-export --route 宁夏河北
```

默认生成 `data/x001-freight.csv`（UTF-8 BOM，可直接用 Excel 打开），也可用
`--output` 指定路径。导出仅包含指定线路中已完成识别的记录；缺少关键字段
或识别流程标记的疑义会汇总到「待核对项」，未展示的需要车数显示为「未显示」。
未能确认线路的记录不会混入指定线路导出。

### 遍历与结束条件

- 列表中出现折叠提示时，程序先展开，再按新的页面布局重新定位货源。进详情后分屏截图，返回列表后重新识别卡片。
- 路线文字为已读浅灰色的货源会直接跳过，包括本轮开始前已打开过的货源。当前屏没有可采货源或折叠入口时，程序继续向下浏览列表。
- 程序根据相邻页面重叠的卡片、文字摘要和图像特征减少本轮重复访问。身份有歧义时保留两条。不同运价或装货时间可以分别入库。
- 识别到「推荐货源」分区后，只采集该分区上方的普通货源，不打开推荐区卡片；待上方货源处理完毕，程序回到同一线路顶部、下拉刷新并继续循环。卡片摘要可匹配的本轮已采货源会跳过；达到 `--max-orders` 时停止。
- 遇到列表末尾时结束。连续三次翻页没有进展时，控制台会提示未确认到达末尾。达到 `--max-orders` 时直接结束。

## 截图与数据库

SQLite 视图 `freight_report` 按人工表列序显示货源，查询可用
`SELECT * FROM freight_report ORDER BY 序号`。该视图展示包装、运价口径和备注，
有疑义的字段带「待核对」标记。原图和 OCR 文本仍可通过 `captures`、`freight` 查阅。
已有记录可在采集停止后用 `uv run x001-collect --reprocess-all` 重做清洗。

默认截图位于 `data/captures/<采集编号>/`。自定义数据库文件使用其同目录下的 `<数据库文件名>-captures/`。每组包含列表原图 `card.png` 和按编号排列的详情图 `detail-01.png` 等。

「货源反馈」浮层遮挡字段时，程序先查找已有截图中的完整值，必要时最多短滑补拍两次。补拍文件名包含 `-supplement`。仍无法确认的字段留空，字段名写入 `review_fields`。PP-OCRv5 二次意见和原始文字另存到 `freight.second_opinion`；严格一致的重量范围分隔符纠正会记录在 `applied_fields`。运价单位只有在详情识别与列表价格完全一致时才补齐。常见包装尾字 OCR 错误会按明确的包装词形修正，无法识别的残字会标记复核。其他字段意见不自动覆盖主结果，并在导出核对项中展示。若二次引擎初始化或推理失败，错误会单独记录，采集仍保留 Windows 主结果并将相关字段留给人工核对。
装货时间识别会修复 OCR 将时间范围短横线与数字「1」合并识别为「刁」的情况；其他无法确认的时间仍会标记待核对。

| 表 | 内容 |
| --- | --- |
| `captures` | 采集时间（UTC）、线路、卡片摘要、截图相对路径、处理状态、错误信息和 OCR 耗时。 |
| `freight` | 每个采集编号对应一条识别结果，包含十项货源字段、主引擎 OCR 原文、待核对字段和可选的二次识别意见。 |

数据库将采集时间按 UTC 保存；网页显示本地时间，今天、昨天和指定日期筛选也按本地日历计算。

货源字段包括运价 `price`、货物重量 `weight`、预估里程 `estimated_distance`、车型要求 `vehicle`、需要车数 `truck_count`、其他信息 `other_info`、卸货地 `unloading_location`、装货地 `loading_location`、货主 `shipper` 和货物 `cargo`。截图未展示或无法确认的值在 SQLite 中为 `NULL`，运价保留页面显示的单位或「电议」。

按 `Ctrl+C` 可中断采集。完整保存的截图组可用 `--process-only` 续处理，同一采集编号重新识别时更新原记录。中断时尚未完成的截图组保留失败状态和已有文件。当前线路、界面布局和 OCR 结果会影响覆盖率，重要字段可用原图复核。

### 常见故障

- ADB 显示 `unauthorized` 时，在手机上确认 USB 调试授权，再运行设备检查命令。
- 程序提示无法确认线路时，检查手机是否回到了原线路的货源列表，再启动下一轮。
- OCR 失败时，可先查看 `captures.error`，再用 `--process-only` 重试。若 Windows OCR 初始化失败，检查是否安装了简体中文 OCR 语言包；二次识别首次运行需联网下载模型。

## 单图 OCR

`x001-ocr` 使用 RapidOCR 的 PP-OCRv5 mobile/OpenVINO CPU 模型识别本地图片，按行输出文字。旧 PP-OCRv6 Medium 仍可通过采集参数 `--ocr paddle` 使用。`x001` 是同一个命令的别名。

```powershell
uv run x001-ocr "D:\images\freight.png"
```

```python
from x001.ocr import OCRRecognizer

recognizer = OCRRecognizer()
texts = recognizer.extract_text("freight.png")
```

## 开发维护

| 模块 | 职责 |
| --- | --- |
| `collect.py` | 线路遍历、折叠展开、详情截图、补拍和采集进程调度。 |
| `export.py` | 按线路筛选已完成记录，校验必填字段并导出可交付 CSV。 |
| `adb.py` | ADB 截图、UiAutomator 点击和滚动。`scroll()` 的 `region` 使用屏幕像素，`up` 指手指上滑。 |
| `vision.py`、`freight.py` | 识别列表卡片、匹配重复访问、提取详情字段和检测浮层遮挡。 |
| `engines.py`、`ocr.py` | OCR 后端和独立图片识别入口。 |
| `storage.py` | SQLite 任务队列、结果写入和中断恢复。 |
| `filters.py` | 网页筛选与 Excel 导出共用的参数化数据库条件。 |
| `web.py`、`web_static/` | 本地网页操作台、查询接口、运行控制和静态页面。 |
| `launcher.py` | Windows GUI 启动器；准备运行环境并启动本地网页服务。 |

采集与 OCR 通过 SQLite 任务状态协调。截图组完整提交后才进入识别队列。UiAutomator 在手机端分段执行曲线手势，列表和详情各自指定滚动区域。开发时可为 `ADBController` 设置固定 `seed`，复现同一手势；测试直线手势时可设置 `humanize=False`。

更多模块关系、数据状态和开发约定见[项目结构与开发指南](docs/project-guide.md)。

### 离线地图资源

首页不依赖在线地图 SDK、字体或密钥。`web_static/china-map.json` 保存阿里云 DataV 的全国省级边界（https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json，2026-11-13 获取），城市近似中心坐标与参考走廊保存在 `web_static/atlas-data.json`。走廊参考《国家公路网规划（2022）》的主要节点，仅为城市间示意连线，不是精确道路几何。县级走廊节点按所在城市市域查找货源，并在列表注明市域；地点匹配只使用明确地名，不按线路省份猜测。

地图地名覆盖河北、天津、宁夏及北京、山西、陕西、内蒙古、甘肃、山东、河南，共 99 个城市/地区和 5 个参考走廊节点。三地另有 205 个区县：河北 167、天津 16、宁夏 22。通过「地图范围」聚焦区县，或在「查找城市或区县」中定位；区县货源按明确地址匹配，同名区县需要所属城市消歧。地名采用 DataV 离线快照，不宣称反映最新行政区划变化。维护者可显式运行 `python scripts/update_atlas_places.py` 更新资源，正常使用不联网。
